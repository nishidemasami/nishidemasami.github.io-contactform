# タスクリスト (MoSCoW分析)

このプロジェクトの要件や課題、今後予定されている機能を、AIエージェントが自律的に作業できるように MoSCoW (Must, Should, Could, Won't) 形式で分類したリストです。

## Must Have（必須要件：プロジェクトの目的を果たすために不可欠なもの）
- [x] Cognito を用いた認証基盤の構築
- [x] Aurora DSQL 上での Liquibase を用いたテーブル (`inquiries` など) 作成
- [x] Rust Lambda による `GET /inquiries` (自身の問い合わせ一覧取得) の実装
- [x] Rust Lambda による `POST /inquiries` (問い合わせ作成) の実装
- [x] フロントエンド (Next.js) からの問い合わせ投稿・一覧表示機能
- [x] GitHub Actions を使った CI/CD パイプラインの構築
- [ ] **管理者向けの問い合わせ一覧表示機能 (`GET /admin/inquiries` などの実装)**
  - 現状はユーザー自身の問い合わせしか取得できないため、管理者が全体を把握するAPIが不足している。
- [ ] **管理者による問い合わせへの回答機能 (`PUT /admin/inquiries/{id}/reply` などの実装)**
  - DBには既に `reply`, `respondent`, `reply_at` カラムが存在するが、APIとフロントエンドから操作する手段がない。

## Should Have（推奨要件：重要だが、リリースや運用開始をブロックしないもの）
- [ ] **Next.js フロントエンドの E2E テストの追加**
  - 現在 `testpage` ディレクトリにリンターやビルドの設定はあるが、Playwright や Cypress などを利用したE2Eテストが不足している。AIによるフロントエンド実装の品質担保に必要。
- [ ] **ユーザーによる自身の問い合わせの削除機能 (`DELETE /inquiries/{id}`)**
  - 間違えて投稿してしまった場合の取り消し手段の提供。
- [ ] データベースのバックアップおよびリカバリ計画の明文化
  - 万が一の障害時にデータ損失を防ぐための手順の確立。

## Could Have（可能であれば：時間やリソースに余裕があれば実装したいもの）
- [ ] 問い合わせに対するステータス管理 (`未対応`, `対応中`, `完了` など) の導入
  - 現状は `reply` の有無で判断するしかないため、より詳細な状態管理があると便利。
- [ ] 管理者が回答を行った際の、ユーザーへの自動メール通知 (SES などを利用)
  - ユーザーがわざわざサイトを確認しに来なくても、回答があったことを通知できる。
- [ ] 本番環境用ダッシュボードの構築
  - 管理者が日々の問い合わせ件数や未回答の件数を視覚的に把握できるUI。

## Won't Have（今回は見送る要件：現在のスコープ外、または将来のフェーズで検討）
- [ ] チャットボットによる自動応答システム
- [ ] 複数言語対応（多言語ローカライズ機能）
- [ ] ユーザー間での問い合わせの公開フォーラム化
