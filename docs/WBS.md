# WBS (アジャイル開発用)

このドキュメントは、プロジェクトのバックログをEpic、Feature、User Storyの階層構造で管理するためのWBS（Work Breakdown Structure）です。スクラムやアジャイル開発のイテレーション計画に利用します。

## Epic 1: フロントエンドの品質向上
**説明**: ユーザーが操作するフロントエンド (`testpage`) の信頼性と保守性を高めるため、テスト環境を整備する。

- **Feature 1.1**: 単体テスト環境の構築
  - **Story 1.1.1**: Vitest (または Jest) と React Testing Library の依存関係を `package.json` に追加する。
  - **Story 1.1.2**: テスト実行用のスクリプト (`pnpm test`, `pnpm test:watch` 等) を設定する。
  - **Story 1.1.3**: GitHub Actions の `document_cicd.yaml` にテスト実行ステップを組み込む。

- **Feature 1.2**: 基本コンポーネントのテスト実装
  - **Story 1.2.1**: `AmplifyProvider` などの共通コンポーネントの単体テストを記述する。
  - **Story 1.2.2**: 各種ビューコンポーネント（ログイン、一覧、新規作成）の表示に関するテストを記述する。

## Epic 2: バックエンドAPIの堅牢性向上
**説明**: APIの安全性とデータ整合性を高めるため、入力値のバリデーションを厳密に行う。

- **Feature 2.1**: リクエストのバリデーション実装
  - **Story 2.1.1**: `CreateInquiryRequest` に対する入力文字数・形式のバリデーション処理を実装する。
  - **Story 2.1.2**: 不正な入力に対する適切なエラーレスポンス (400 Bad Request) とエラーメッセージを定義する。
  - **Story 2.1.3**: バリデーション処理に対する単体テスト (Rust) を追加する。

## Epic 3: ドキュメントと可視化の改善
**説明**: プロジェクトの状態（品質指標やアーキテクチャ）をチーム全体で把握しやすくする。

- **Feature 3.1**: カバレッジレポートの可視化
  - **Story 3.1.1**: バックエンド (`cargo tarpaulin`) の結果を HTML レポートとして生成し、成果物として保存する。
  - **Story 3.1.2**: フロントエンドのカバレッジレポートを生成するようテスト設定を変更する。
  - **Story 3.1.3**: 生成された各種カバレッジレポートへのリンクをWiki (`README.md` など) に追加する。
