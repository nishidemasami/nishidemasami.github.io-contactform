# WBS (アジャイル向け)

タスクリスト (MoSCoW分析) に基づき、アジャイル開発向けの Work Breakdown Structure (WBS) を Epic, User Story, Task の粒度で定義します。

## Epic 1: プロジェクトの自律的AI化の推進
**目的**: AI エージェントが自律的に開発や保守作業を行えるように、指示書とルールを整備する。

- **User Story 1.1**: AI が適切なコンテキストで開発できるよう、ルートディレクトリに AI 指示書を配置する。
  - **Task 1.1.1**: ルートに `AGENTS.md` を作成する。
  - **Task 1.1.2**: `docs/` 以下の知識ベースを参照するよう `AGENTS.md` にルールを記述する。

- **User Story 1.2**: AI と人間がコードレビューをスムーズに行えるよう、PR テンプレートを導入する。
  - **Task 1.2.1**: `.github/pull_request_template.md` を作成する。
  - **Task 1.2.2**: PR テンプレート内にテスト結果や影響範囲の記載項目を設ける。

## Epic 2: ドキュメントの完全化と保守性向上
**目的**: 開発者（人間および AI）がシステム全体を容易に理解できるよう、ドキュメントの未完成部分を解消する。

- **User Story 2.1**: API とフロントエンドの README に記載漏れを補完し、全体の理解を促進する。
  - **Task 2.1.1**: `api/README.md` の `[WIP]` セクションに各ソース（Rust実装、OpenAPIファイルなど）の説明を追記する。
  - **Task 2.1.2**: `testpage/README.md` の `[WIP]` セクションに Next.js や設定ファイルの説明を追記する。

- **User Story 2.2**: 本 WBS やタスクリストを Wiki から容易に参照できるようにする。
  - **Task 2.2.1**: `docs/TASKS.md` と `docs/WBS.md` を `docs/SUMMARY.md` と `docs/README.md` にリンクとして追加する。

## Epic 3: 自動テストの拡充による品質保証
**目的**: 自律的 AI や人間が安全にコードを変更できるよう、E2E テストや結合テストを強化する。

- **User Story 3.1**: フロントエンドの UI 操作が正常に機能し続けることを保証する。
  - **Task 3.1.1**: `testpage` プロジェクト内に Playwright などの E2E テストツールをインストール・設定する。
  - **Task 3.1.2**: ログインから問い合わせ作成までの基本フローを E2E テストとして実装する。
  - **Task 3.1.3**: CI/CD パイプラインにフロントエンドの E2E テスト実行プロセスを追加する。

- **User Story 3.2**: API のエンドポイントが意図通りに動作することを保証する。
  - **Task 3.2.1**: API 結合テスト用のフレームワークやスクリプトを導入する。
  - **Task 3.2.2**: `/inquiries` の主要なエンドポイントに対するテストケースを実装する。

## Epic 4: 開発効率と CI/CD パイプラインの最適化 (Could Have)
**目的**: 依存関係の管理と CI/CD 実行時間の最適化を行う。

- **User Story 4.1**: 常に安全で最新のパッケージを使用できるようにする。
  - **Task 4.1.1**: Dependabot (または Renovate) の設定ファイルを追加する。

- **User Story 4.2**: CI パイプラインの実行速度と安定性を高める。
  - **Task 4.2.1**: 各 `.yaml` ワークフローの重複処理を見直し、キャッシュ機構を最適化する。
